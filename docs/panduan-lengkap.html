    Panduan Lengkap Sistem

    Dari nol sampai produksi: setup Supabase, akun engineer, semua fitur CRM outreach & referral 10%, aturan uang, SOP harian, keamanan, sampai troubleshooting.

    Vue 3 + Vite Supabase (Postgres + Auth + RLS) Vercel 1 engineer
    Dokumen ini dihasilkan dari kode yang benar-benar ada di repo · 15 file SQL · 11 suite database · 39 unit test
    Bagian 1

    Ringkasan & arsitektur

    Sistem ini adalah website jasa (publik) plus dashboard internal untuk mengelola prospek dari Instagram, klien, proyek, pembayaran, dan komisi referral 10%. Semuanya satu aplikasi — bukan dua sistem terpisah.

    Apa yang bisa dilakukan

    Publik
    Landing, layanan, harga, form request + upload, tracking order, portal partner
    Outreach
    Akun target, prospek, import CSV, antrean DM, template, log respons
    Uang
    DP, pelunasan, refund, void, komisi 10%, payout, rekap

    Alur besar

    IG angkatan→ Prospek→ DM manual→ Klien / Proyek→ Pembayaran→ Komisi 10%

    Arsitektur teknis

    LapisanTeknologiPeran
    FrontendVue 3.5 (SFC, <script setup>), Vite 8, Vue Router 5, Pinia 4, Tailwind 3Website publik + dashboard admin dalam satu SPA
    BackendSupabase: PostgreSQL, Auth, Row Level Security, PostgREST, RPC SQLSemua baca/tulis data; tidak ada server API sendiri untuk CRUD
    Fungsi serverVercel Functions (api/)Hanya untuk hal ber-secret: webhook Instagram, email, Telegram
    Penyimpanan fileSupabase Storage bucket attachmentsLampiran request; privat + signed URL
    DeployVercel (alias jokitugasit.my.id)Build statis + functions

    Prinsip yang tidak boleh dilanggar

    • Satu engineer. Tidak ada tim sales, tidak ada agensi, tidak ada multi-tenant.
    • Tidak ada bot Instagram. Tidak ada scraping followers, tidak ada cold DM massal, tidak ada penyimpanan cookie/password IG.
    • Uang dihitung database. Komisi 10% tidak pernah dihitung di browser.
    • RLS adalah otorisasi. Menyembunyikan menu di Vue bukan pengamanan; policy database yang menentukan.
    • Migration additive. Tidak ada db reset ke data nyata.

    Istilah. "Prospek" = orang yang belum jadi klien. "Lead" dipakai bergantian. "Proyek" dan "request" adalah hal yang sama: satu baris di tabel requests.

    Bagian 3

    Setup database Supabase

    Ini bagian paling kritis. Urutan migration tidak boleh diacak karena fungsi saling bergantung.

    3.1 Cara tercepat (satu tempel)

    1. Backup dulu
      Supabase Dashboard → Database → Backups. Pastikan backup harian aktif. Kalau data masih kosong, tetap lanjut.
    2. Buka SQL Editor
      Dashboard → SQL Editor → New query.
    3. Tempel seluruh supabase/DEPLOY-ALL-IN-ONE.sql
      File ini berisi gabungan 10 migration terakhir dan bersifat idempoten — aman dijalankan berulang.
    4. Klik Run, lalu verifikasi
      Jalankan query verifikasi di bawah. Harus muncul 6 dan 4.
    -- 1. Enam fungsi inti harus ada
select proname from pg_proc
where proname in ('void_payment','import_prospects_batch','analytics_campuses',
                  'register_partner','rotate_partner_code','delete_prospect')
order by 1;

-- 2. Empat kolom baru di requests
select column_name from information_schema.columns
where table_schema = 'public' and table_name = 'requests'
  and column_name in ('campus','stack','source','prospect_id')
order by 1;

    Kalau DEPLOY-ALL-IN-ONE.sql belum memuat perubahan tertentu, jalankan file berikut sesuai urutan:

    5migration-security-hardening.sqlWajib. Menutup kebocoran RLS, membuat is_engineer()
    6migration-outreach-schema.sqltarget_accounts, prospects, dm_templates, outreach_logs
    7migration-money-schema.sqlpayments, commissions, analytics, portal partner
    8migration-payment-flow.sqlStatus proyek dari pembayaran, void_payment

    3.4 Rollback database

    Semua migration bersifat additive (tambah tabel/kolom/fungsi). Untuk mengembalikan satu fungsi, jalankan ulang definisi lamanya dari file migration sebelumnya. Tidak ada perintah yang menghapus data.

    -- Contoh: kembalikan analytics_overview ke versi tanpa filter kampus
-- jalankan ulang definisi dari migration-analytics-source.sql

-- Nama fungsi yang tersedia (tanpa p_from/p_to/p_campus):
select proname, pg_get_function_arguments(oid)
from pg_proc
where proname in ('analytics_overview','analytics_funnel');
    Bagian 4

    Akun engineer & login

    Tidak ada halaman daftar admin. Akun dibuat manual, lalu role-nya dinaikkan menjadi engineer.

    1. Buat user di Supabase
      Dashboard → Authentication → Users → Add user. Isi email + password, centang auto confirm.
    2. Pastikan baris profiles ada
      Trigger handle_new_user() membuat baris profil otomatis. Kalau tidak, buat manual:
    insert into public.profiles (id, full_name, email, role)
values ('<user-uuid>', 'Nama Engineer', 'email@contoh.com', 'engineer')
on conflict (id) do update set role = 'engineer';

-- Cek
select id, email, role from public.profiles;
    1. Login di aplikasi
      Buka /login. Kalau role bukan engineer, login ditolak dan sesi langsung dihapus — ini disengaja.

    Role disimpan di profiles.role dan dibaca fungsi is_engineer(). Jangan mengandalkan penyembunyian menu di Vue — policy RLS yang menolak akses data.

    Bagian 6

    Deploy produksi

    Satu perintah menjalankan seluruh siklus: test → build → migration → push → deploy → smoke test.

    make redeploy

    6.1 Sekali saja: siapkan kredensial database

    Migration otomatis butuh connection string. Simpan di file terpisah (bukan di .env repo):

    mkdir -p ~/.config/jokitugasit
cat > ~/.config/jokitugasit/db.env <<'EOF'
SUPABASE_DB_URL="postgresql://postgres.<ref>:<PASSWORD>@<host>:5432/postgres?sslmode=require"
EOF
chmod 600 ~/.config/jokitugasit/db.env

    Ambil URI dari Supabase → Project Settings → Database → Connection string (URI). Ganti <PASSWORD>.

    make memakai /bin/bash non-interaktif yang tidak membaca ~/.zshrc. Karena itu scripts/redeploy.sh memuat file db.env sendiri. Lokasi bisa diganti dengan DEPLOY_ENV_FILE.

    6.2 Tujuh langkah yang dijalankan

    #LangkahGagal →
    0Preflight: branch main, node/npm/git/vercel/psql, cek koneksi DBberhenti
    1npm testberhenti
    2npm run test:db (kalau Postgres lokal hidup)berhenti
    3npm run buildberhenti
    4Backup schema → apply DEPLOY-ALL-IN-ONE.sql → verifikasi 6 fungsi + 4 kolomberhenti
    5Commit + git push origin main (retry 3×)berhenti
    6vercel --prod (retry 3×)berhenti
    7Smoke test 5 route publikberhenti

    6.3 Opsi

    FlagEfek
    --checkPreflight saja, tidak mengubah apa pun
    --self-testUji skrip + bundle SQL (tanpa deploy)
    --skip-testsLewati unit + DB test
    --skip-dbLewati migration (SQL sudah dijalankan manual)
    --skip-pushLewati commit/push
    --skip-deployLewati Vercel + smoke
    --only-dbHanya migration
    --only-deployBuild + deploy saja (hotfix frontend)
    --db-url <url>Connection string langsung
    --backuppg_dump -Fc penuh sebelum migration
    --message "..."Pesan commit kustom
    --allow-branchIzinkan branch selain main

    6.4 Contoh nyata

    # deploy penuh (paling sering)
make redeploy

# SQL sudah dijalankan manual, hanya frontend
make redeploy ARGS="--skip-db"

# cek prasyarat tanpa mengubah apa pun
make redeploy ARGS="--check"

# hanya memperbaiki database
make redeploy ARGS="--only-db --db-url postgresql://..."

# backup penuh dulu, lalu deploy
SUPABASE_DB_URL="postgresql://..." make redeploy ARGS="--backup"

    6.5 Rollback

    vercel rollback                              # kembali ke deployment sebelumnya
git revert <sha> --no-edit && git push origin main

# mematikan modul CRM tanpa rollback kode
vercel env add VITE_ENABLE_CRM production    # isi: false
make redeploy ARGS="--only-deploy"

    7.1 Alur form request

    1. Klien isi form
      Nama, WhatsApp, kategori, deadline, deskripsi, link (opsional), lampiran (opsional), kode referral (opsional).
    2. Lampiran diunggah
      Maks 10 MB, tipe PDF/ZIP/PNG/JPG/WEBP/TXT. Disimpan sebagai path di bucket privat.
    3. Server membuat nomor order
      RPC create_public_request. Nomor 6 digit acak (tidak mudah ditebak). Status dipaksa new, harga & catatan internal dikosongkan — klien tidak bisa memalsukan.
    4. Kode referral divalidasi
      Hanya kode partner aktif yang disimpan. Kalau nomor WhatsApp klien sama dengan nomor partner → kode dibuang (self-referral).
    5. Klien dapat nomor tiket
      Diarahkan ke /success/:orderNo, lalu bisa cek di /track.

    7.2 Portal partner

    Partner memasukkan kode referral untuk melihat: nama, kode, kampus, jumlah referral, jumlah deal, total dibayar, total tertunda, dan daftar komisi (order, kategori, status, nominal, tanggal).

    Portal memakai RPC partner_portal(kode) yang hanya mengembalikan baris milik partner tersebut. WhatsApp, e-wallet, dan data partner lain tidak pernah ikut keluar.

    ig_username,display_name,campus,cohort_year
@Andi.23,Andi Pratama,Binus,2023

    Kolom wajib
    ig_username (header opsional; tanpa header urutan kolom tetap sama)
    Normalisasi
    spasi dibuang, @ dihapus, jadi huruf kecil
    Validasi
    format [a-z0-9._]{1,30}; angkatan 1990–2036

    Suppression

    8.7 Konversi prospek → klien

    1. Klik "Jadikan Klien"
      Modal terbuka: kategori, ringkasan kebutuhan, quote awal (opsional).
    2. Buat Proyek
      RPC create_request_from_prospect membuat requests dengan source = DIRECT_DM, campus dari prospek, prospect_id terisi, status consultation.
    3. Prospek ditandai CONVERTED
      Tombol berubah "Sudah klien". Konversi kedua ditolak (unique index).
    4. Lanjut ke detail proyek
      Klik "Buka detail proyek →" untuk mengisi quote final, DP, dll.

    Prospek berstatus DNC tidak bisa dikonversi. RPC menolak dengan DNC_LOCKED.

    Bagian 10

    Aturan uang & status

    Bagian ini tidak boleh diubah tanpa menambah test. Semua nominal integer rupiah; tidak ada float.

    10.1 Rumus

    total_tagihan      = quote_amount − discount_amount        (minimum 0)
net_dibayar        = (DP + pelunasan) − refund             (hanya status CONFIRMED)
eligible_komisi    = total_tagihan − refund                (hanya jika net_dibayar ≥ total_tagihan)
komisi             = eligible_komisi × rate_bps / 10000    (integer, dipotong/truncate)
rate_bps           = 1000  → 10%

    Baru DP 50%1.000.00050.000475.0000PENDING
    Lunas1.000.00050.000950.00095.000ELIGIBLE
    Lunas + refund 100.000500.0000400.00040.000ELIGIBLE
    Refund penuh300.000000VOID
    Refund setelah dibayar1.000.0000750.000tetap 100.000ADJUSTMENT
    Nominal ganjil333.3330333.33333.333ELIGIBLE

    10.4 Anti-fraud

    • Satu proyek satu partner. Unique index pada commissions.request_id.
    • Self-referral ditolak. Nomor WhatsApp dinormalisasi (0831… = 62831…); kalau sama dengan partner, kode dibuang dan komisi tidak pernah dibuat.
    • Idempotensi. record_payment memakai idempotency_key unik.
    • Tidak ada double payout. mark_commission_paid hanya menerima status ELIGIBLE.
    • Refund tidak menghapus histori. Nominal yang sudah dibayar tidak ditulis ulang; status jadi ADJUSTMENT untuk review manual.

    Komisi tidak pernah dibayar dari DP. Hanya setelah pelunasan terverifikasi. Ini aturan bisnis yang ditegakkan database, bukan sekadar kebiasaan.

-- Pembayaran & komisi sebuah proyek
select r.order_no, r.status, r.quote_amount, r.discount_amount,
       coalesce(sum(p.amount) filter (where p.kind<>'REFUND'),0) as dibayar,
       c.status as komisi_status, c.amount as komisi
from public.requests r
left join public.payments p on p.request_id=r.id and p.status='CONFIRMED'
left join public.commissions c on c.request_id=r.id
where r.order_no='<NOMOR>'
group by r.id, r.order_no, r.status, r.quote_amount, r.discount_amount, c.status, c.amount;

    StatusArtiManual DMOtomatis
    UNKNOWNDitemukan/diimpor, belum diputuskanBoleh, setelah reviewTidak
    OPTED_INMenyatakan setuju dihubungiBolehBoleh
    OPTED_OUTMenolak / minta berhentiTidakTidak

    Di /ops/prospects: filter consent, badge per baris, tombol Opt-in / Opt-out. Opt-out otomatis menyalakan DNC; re-import tidak menghapusnya. Lepas DNC mereset consent ke UNKNOWN — bukan diam-diam opt-in.

    Keputusan dihitung database lewat outreach_eligibility(prospect, channel). Kanal AUTOMATED_DM butuh OPTED_IN; MANUAL_DM boleh untuk UNKNOWN setelah Anda meninjau.

    17.2 Membuat campaign

    1. Buka /ops/campaigns
      Klik Buat Campaign.
    2. Isi tujuan & channel
      Distribusi Admin / Outreach Personal / Referral / Inbound; channel DM manual, IG Story partner, WhatsApp referral, atau website opt-in.
    3. Isi biaya & nilai waktu
      Dipakai menghitung CAC. Boleh 0, tetapi CAC jadi tidak jujur jika waktu tidak dihitung.
    4. Salin link
      Format: /request?campaign=CMP-XXXXXXXX&utm_source=instagram&utm_medium=…&utm_campaign=…. Tambahkan &ref=REF-… bila ingin atribusi referral.
    5. Tambah target
      Pilih akun angkatan; tandai status Direncanakan / Dihubungi / Izin diberikan / Menolak / Jadi klien.

    17.3 Event & atribusi

    EventKapan tercatat
    INQUIRYRequest masuk dengan kode campaign
    DEALProyek mulai dikerjakan (status berubah)
    PAIDProyek lunas
    REFERRAL_PAIDKomisi partner ditandai lunas

    Atribusi dikunci setelah request dibuat (first valid touch). Mengubah campaign proyek setelah deal ditolak database. Kode campaign yang tidak aktif diabaikan — request tetap masuk sebagai INBOUND.

    17.4 Metrik & CAC

    conversion = klien lunas / inquiry
CAC        = (biaya campaign + nilai waktu) / klien lunas

    Kartu campaign menampilkan inquiry, deal, lunas, dan CAC. Jika klien lunas < 5, UI menandai data masih kecil — jangan menyimpulkan pemenang channel dari sample sekecil itu. Dashboard juga menampilkan ringkasan kampanye pada periode yang dipilih.

    17.5 Feature flag

    FlagDefaultMengontrol
    VITE_ENABLE_CRMtrueSeluruh modul CRM
    VITE_ENABLE_OUTREACHtrueTarget, prospek, DM, template
    VITE_ENABLE_CAMPAIGNStrueHalaman kampanye

    Inbound API tetap OFF. Tidak ada auto-reply, scraping followers, atau blast DM. Aktivasi hanya setelah app review Meta, token, window respons, dan aturan messaging diverifikasi. Sampai itu, semua balasan manual dari aplikasi Instagram.
